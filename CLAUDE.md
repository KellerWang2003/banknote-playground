# CLAUDE.md

Banknote Playground: a design tool for previewing lenticular security threads on banknotes (Oberthur Fiduciaire x ArtCenter studio). See README.md for what it does and the code layout.

The app is called Banknote Playground (renamed from Security thread playground on 3 November): page title, sign-in page, project list, package name. Production is the Vercel project `banknote-playground`, deployed from the GitHub repo KellerWang2003/banknote-playground, at banknote-playground.vercel.app. Keep of-playground.vercel.app: it serves the same deployment with no redirect, since a browser keeps its username, settings and offline copies per address and the old link has been shared. Older names stay on purpose where renaming would risk users' data for nothing they see: the Supabase table, bucket and function (`thread_playground_projects`, `thread-playground-artwork`, `thread-workspace`) and the `of-playground.*` browser storage keys (renaming those resets what users' browsers remember). The folder was renamed to match (it was `OF Security Thread Playground`), and so was the parent folder's launch config (`banknote-playground`, was `thread-playground`).

## Commands

- `npm run dev`: dev server. From the parent folder, the `banknote-playground` launch config runs it on port 5174.
- `npm run build`: type-check (TypeScript 7) and build. Run it before every commit.
- `npm run lint`: Oxlint. `src/components/ui/**` (generated shadcn code) is ignored.

## Working with Keller

- **Branches:** the app has live users, and main deploys to them through Vercel. Do all work on the `dev` branch, or a feature branch off it, and commit and push there. Merge into main or push main only when Keller explicitly says to in that conversation. The Supabase backend is shared by every branch, so treat database, function or template changes as live too, and check with Keller first.
- Plan first. Don't write code until Keller says to build. A scope change or "let's focus on X" means update the plan, not implement it.
- He iterates by giving feedback on the running app. Commit after each round, with a message that says what changed.
- Call notes "banknotes" in the UI.
- No tutorial or hint text in the UI. Keep only what's needed, and name terse field labels in a `title` tooltip instead. Where a control is hard to grasp the first time (1 → 5, Cycle), use `Explain` (`src/editor/LensVisuals.tsx`): a hover tooltip with a small picture and one line. The one tip that shows by itself, at Keller's ask (3 November): the first thread added in a new project (banknotes come without one, see Threads) opens on its Thread tab with "You can add windows here" in a tooltip beside the Windows card (`WindowsCard`'s `tip`), since banknotes start without windows; the next click or key anywhere ends it, and that click still does what it lands on (switching Windows on, say).

## UI rules

- Use shadcn components for every control (`npx shadcn@latest add <name>`, base-nova style, Base UI primitives). Don't hand-roll buttons, inputs, menus or dialogs. Compose them in `src/components/controls.tsx`. Keller will restyle `src/components/ui` and the tokens in `src/index.css` later.
- After adding a component, replace `from "cn"` with `from "@/lib/utils"` in the generated files.
- Number fields are Figma-style `ScrubField`s (drag the label to scrub), not sliders. Typed past its limits, a field drops the value once it is left; a `strict` length field (a banknote's size) keeps it instead, marked as an error with the limit under it (`limitErrors`), until it is fixed.
- Lengths are always mm in the code and in saves; only how they read changes (see Units below). A length field is a `LengthField` (`LengthNumberField` in a dialog), which takes and gives mm and carries the unit menu on its unit; a length in text goes through `formatLength` or `lengthIn` with the unit from `useLengthUnit` (`src/lib/units.ts`). Never write "mm" after a length by hand.
- **Visual hierarchy** (Keller asked for one set on 3 November; follow it everywhere):
  - Type, five steps in the panels: 14px (`text-sm`) for content: list rows, values in fields, inputs, menus. 13px (`text-[13px]`) for panel headings: the right panel's part tabs and `Group` titles. 12px (`text-xs`) for labels: field labels, counts. 11px (`text-[11px]`) for the small label over each control in a side panel (`Labeled`, regular weight, always shown, as Figma's property labels: Keller wants no one guessing what T or a strip means; leave it off only where a word in or beside the control already says it) and for small headings: `Section` titles, Banknotes · n, Presets, Sections · n, the export dialog's, in sentence case. 10px (`text-[10px]`) for notes on chips and in pictures (frame numbers on clips, durations); pictures may go smaller. Only the project list and sign-in pages go larger.
  - Weight: 400 for values and body, 500 for anything interactive (buttons, tabs, rows) and small headings, 600 for headings (`Group` titles, the open tab).
  - Buttons: primary (filled, the default variant) is the one main action of a panel or section: Export (in the corner bar, top right), Edit in Thread Studio above the timeline while a thread is picked, a dialog's confirm, New project, Continue. Secondary (`outline`) is a standalone action beside a primary or where a filled one would shout: Cancel, Replace or Upload an image, Import, presets and strips in the thread editor. Ghost (`ghost`, `IconButton`) is for toolbars and inline actions: add, duplicate, delete, undo, zoom, menus, rows. Destructive only confirms a delete in a dialog.
  - Dividers, two levels (Keller): dark, full width (`border-border`, as the `Separator` under the project name) under a panel's header and between groups or other big sections; lighter and inset with padding (`border-border/70`, a `Group`'s own `divide-y`) between the sections inside one. Panel outlines stay `border-border/70`.
  - Corners (Keller asked for one radius on 3 November): every floating panel has the same corners, 15 px (`--radius` + 6 px + the 1 px border, so `rounded-lg` controls inset 6 px sit concentric inside), set once on `Panel`; don't give a panel its own rounding. That covers the Banknotes panel, the corner bar, the right panel, the tilt pad, the playback bar, and Thread Studio's top bar, panels and zoom bar, which copies the canvas's corner bar. Controls inside keep `rounded-lg` or smaller, and small labels on a drawing (Thread Studio's measures and the window measures on the canvas, `Measure`) keep their own.
  - Fills (Keller, 4 November): every control with a box has a 90% fill, so a banknote under a see-through panel doesn't show through it, each in its own colour: number fields (`ScrubField`) and selector tracks grey (`bg-muted/90`), dropdowns (`SelectTrigger`), colour fields and outline buttons white (`bg-background/90`). Tabs and icon buttons have no box and stay clear, and a button that sets its own colour keeps it (Thread Studio's tinted frame and strip buttons). A colour field's swatch has a faint outline, so white still shows on the white fill. Selectors (`Segmented`) are Figma's: a grey track as tall as a field, the picked option a white raised pill in dark text, the others grey text (the picked option used to be only a shade darker than the rest).
  - The right panel's part tabs carry their list icons and scroll sideways once they don't fit (`TabStrip`: an edge fades while more lie beyond it, and the open tab scrolls into sight). The zoom percentage shows only in the canvas's corner bar, between − and +, where a click goes to 100%, about true size at the screen's 96 px an inch (Keller took it out on 3 November, as nothing said what 100% was, and wanted it back on 4 November); Thread Studio's zoom bar has none.
- New UI copies what is already there rather than inventing sizes: match the nearest existing row, field, button or editor (text size, height, padding, radius, selected and hover colours). - **Pasting images** (`src/lib/pasteImages.ts`; Keller, 7 November, so the app works inside Figma's code layers, where images are copied rather than picked from files): every upload slot takes an image pasted with ⌘/Ctrl+V while the pointer is over it, exactly as its file picker would give it: the banknote's Front and Back cards (turning the banknotes to that side, as working on it does), the + on a side without a design, a frame's Tile pattern card (in the panels and the clip's pencil), the watermark's and magnetic ink's Image (`LayerImage`), and the timeline's +, which takes several at once, a frame each. With the pointer over no slot, the slot with the keyboard's focus takes it. A field being typed in keeps a paste of text, but an image still goes to the slot under the pointer. It listens to the paste event itself, which needs no clipboard permission, in a frame as on its own; a copied file, a copied picture and SVG markup copied as text (Figma's Copy as SVG; given the namespaces an image needs when it lacks them, refused with a notice when it can't be read) all paste. Embedded in another page, the pointer coming over a slot brings the keyboard to the app (`window.focus()`), as otherwise ⌘V pastes into the page round it (Figma's canvas). Text, or Figma's own copy of layers (its own format, which only Figma pastes), over a slot gives a notice saying so, the latter how to copy as PNG or SVG. A new upload slot spreads `usePasteImage` (or `usePasteImages`) on its button.
- **Loading states** (Keller, 7 November: "keep it visual and let the layout do the talking"): nothing says it is loading in words. While something is still on its way from Supabase (or being made, as the demo is), its place shows its layout as skeletons, with shadcn's `Skeleton` (`src/components/ui/skeleton.tsx`: a neutral block with a soft light sweeping across it, `skeleton-sweep` in `src/index.css`, fixed to the window so every skeleton on screen shares one wave; `bg-scroll` inside anything that turns or zooms). The project list shows its cards as skeletons (their banknotes as plain paper shimmering, `NoteSkeleton`, bars for the name and count; the Projects count and the save status small skeletons) until the cloud has first answered, for a device with none of the workspace's projects (`listed`, `ProjectSync.listed`; cached projects show at once), and a project being duplicated holds its copy's place with the banknotes it copies. A project's link opened before its project is here, and the demo while it is made, show the editor's layout (`EditorSkeleton`: every floating panel in its place, only the way back working). A banknote's design, a frame's image or magnetic ink's shape still on its way shimmers in its place (NoteView's `Loading`, on screen only: export waits for every image), as do the panels' thumbnails (the design cards, Tile pattern, the watermark's and magnetic ink's Image, the timeline's clips). `useImageUrl` and `useInkMask` give undefined while on the way, which is when to show it loading, and null once it couldn't be had, so nothing shimmers for ever; zooming past the copies keeps the biggest one showing meanwhile. Errors stay in words (the notice, a workspace that couldn't open with Retry). A new view of something that loads follows the same pattern.
- `exportRender.ts` redraws NoteView on a canvas for MP4/GIF export. When you change how NoteView draws a banknote, change the export renderer to match.

## Product decisions

- It's a general tool, not tied to the Flight notes: a project is created with just a name, New banknote asks only for a name and size, and no banknote has a colour of its own: every one is printed on the same very light grey paper (`PAPER` in `src/lib/back.ts`), which shows wherever a side has no design and through a design's transparent parts (Keller, 4 November: "they have to use the design"; a colour saved before stays in the save, unshown, in case it comes back), and banknotes can be any size from 20 mm to 2 m (`NOTE_SIZE`; Keller, 3 November: large ones run to 2000 mm, where it had stopped at 250). There are no built-in denomination presets. A size typed past a limit shows an error under its field, in the right panel and New banknote: the field outlined in red and the limit under it in the unit picked (Max 2000 mm, Min 20 mm; over the maximum as soon as it is typed, under the minimum once Enter is pressed or the field is left, since typing 150 passes 1 and 15). Nothing past a limit is taken, and what typing took on the way (25 and 250 on the way to 2500) goes back; Enter and leaving keep it in the field to be fixed, and New banknote adds nothing until it is. The canvas zooms out to 0.02 so a few 2 m banknotes fit side by side (its dots spread to 500 mm apart); export and the watermark's light layer are drawn at capped sizes, and a 2 m square banknote played at full zoom kept 60 fps.
- **Units** (`src/lib/units.ts`): Keller asked for units beyond metric (3 November). mm, cm, in and pt, mm the default for everyone (no locale guessing); px is left out, since it has no physical size without a ppi. One pick for the whole app, made from the menu on the unit of any length field (the right panel, New banknote), remembered per browser like the panel width, never saved in a project or undone, so switching never changes a value. Each unit reads to its own decimals (mm 0.01, cm and in 0.001, pt 0.1), and the banknote labels on the canvas, the window measures, screen-reader labels and the Checks follow it. Typed values are kept exactly (to a millionth of a mm), and a unit typed after the number (6.14in, 6.14", 15.6cm, 442pt) converts without switching. Scrubbing and the arrow keys (Shift for ten steps) step the largest round number (1, 2 or 5 of a power of ten) of the unit that isn't coarser than the field's mm step: 0.5 mm steps 0.05 cm, 0.01 in or 1 pt, Offset's 0.1 mm 0.01 cm, 0.002 in or 0.2 pt. Canvas and Thread Studio drags keep their mm grid in every unit (0.5 mm, a frame's image 0.1 mm; gaps fill cell by cell on it), so a dragged window can read 0.512 in. Limits stay in mm, and the number shown at a limit can be typed (a banknote's 20 to 2000 mm reads 0.787 to 78.74 in). Thread Studio's fields are `LengthField`s too: L and W (H) beside the thread, and the picked frame image's X, Y and W (0.1 mm steps: 0.01 cm, 0.002 in or 0.2 pt).
- **Frames:** 2 to 5 per banknote. Lenticular optics are not simulated: frames are artwork shown in turn as you tilt.
- **Tilt:** flat sits at the middle of the middle frame by default (frame 3 of 5, frame 2 of 4), so one tilt direction plays on towards the last frame and the other back towards frame 1. Flat is set with the pin on the frame strip in the thread editor's Lens (`FlatStrip`), snapping to half-frame steps (`tilt.flatAt` as a number; 'start' from older saves = 0); the timeline shows it read-only. Hidden frames are always the ones farthest from flat, so moving flat moves them. "1 → 5" sets whether frames run top to bottom (default for new projects; older projects stay bottom to top) or bottom to top, and left to right (default) or right to left. Both live in the small panel off the ⋯ on the Lens title (`LensMenu`, a popover, as two selectors), since they rarely change, with Partial reveal's Wobble under them. Tilt goes to ±90° (`TILT_LIMIT`, edge-on), not a setting: it limits manual tilt and playback (`SWEEP_MAX`) and decides hidden frames. Light and shade on the banknote still scale to full at 60° (`SHADE_DEG`). `tilt.viewDeg` from older saves is ignored. Playback is a project-wide list of moves played in order and looped (`src/lib/moves.ts`, edited in the Playback popover): preset moves (↕ Up/down, ↔ Side to side, Diagonal, Circle) go out from flat and back (up/down and side can start from any angle instead, e.g. swing −12° ↔ +12° without returning to flat; every move starts from flat and returns to flat before the next), by default through one full Cycle on each tilt they use; ⏸ Hold stays flat for its seconds (1 s by default, at 1× and scaled by speed, as ☀ Hold to light's are), so it pauses wherever it sits in the playlist, once the move before it has come back, and nothing else pauses (Keller, 3 November: it replaced Motion's Hold, which paused at full tilt and at flat after every move; `tilt.holdSeconds` from older saves is dropped on load); ⇄ Flip (Keller, 4 November) stays flat while every banknote turns over to its other side, exactly as F does: the tilt loop flips the same switch as each Flip begins (`plan.flips`, `flipsBetween`), so Front | Back follows it and turning over to the backs picks the banknote itself, taking `FLIP_SECONDS` at 1×, scaled by speed as every move is (`plan.flipSeconds`; while playing, F turns at that pace too). Each Flip turns to the other side, so after a pass with an odd number of them the next plays on the other side. Not in Thread Studio, where F does nothing either: there the Flip waits flat (`useTiltLoop`'s `turnsOver`, the canvas's `inStudio`). Export follows it (`turnAt`, `playbackTurns`): it loads both sides, adds the turn to the side tilt as NoteView does (`withTurn`), lays the banknotes out with room for the near edge as they come round edge-on, and plays a playlist that leaves them on their other side twice a loop, so a video ends, and a GIF comes round, on the side it began; its summary reads · from the backs when it starts turned over; a recording (Record a move, the last row of Playback settings' list of moves, which closes the popover, opens the tilt pad and arms it, its ring red, so the next drag on it records; Escape cancels, ahead of any other Escape) is saved to the project's Recordings and becomes the whole playlist on its own; it plays in its own time joined to flat. The Playback settings popover has one plain list of moves on the left (presets, then recordings, then Record a move; click to add to the playlist, recordings can be deleted), the Playlist on the right (reorder, remove, per-move ↕/↔ reach or a hold's seconds), and Motion (speed, curve, fade, in one row) under it. The pad draws the path. Live playback and export read the same plan. Projects without a list play the default playlist, on the tilt the old Tilt setting chose (up/down unless set): a default move (`default-` id, no angles set) glides out a full Cycle and sweeps back to flat, the way 1 → 5 runs, so it stops on the rest frame: 30° → 0° up/down on a new banknote (Keller, 3 November; it had gone 0° → −30° and back). Editing the list keeps it, following the Cycle, until its angles are set; deleting the last recording brings it back. An Up/down or Side to side added from the list swings across the Cycle centred on flat instead. The timeline starts at 0° too. Tilting must read as up vs down (and left vs right), using a strong per-note perspective.
- **Lens effects:** one lens per banknote (`src/lib/lens.ts`), or one per thread section with Mixed angles: the effect, Cycle, flat, band, wobble and 1 → 5 directions are edited for the selected banknote (or section) only (a new banknote starts from the last one's); playback and the tilt pad follow the selected banknote, or the first. Presets Up/down, Side to side, Both ways, Reveal on one tilt, Custom (by tilt or by lens), named by their ridges: Horizontal (plays on up/down), Vertical (side to side), Diagonal 45° (same cycle on both tilts), Partial reveal on one tilt (one tilt plays every frame, the other never shows the outer ones at any tilt up to 90° (`HIDE_LIMIT`), even with the hand drifting `Wobble` degrees (default 1°, set in the Lens title's ⋯ panel; Keller, 4 November: at the old 5° the demo's side tilt changed frame only past about 68°, now from about 34°, and banknotes that never set their own moved with the default) onto the fast tilt: the slow cycle is computed and the hidden count follows from it, never typed: the strip shows the slow tilt's reach as a band whose ends you drag to hide more or fewer frames (`revealLevel`, a step inwards from the widest, the one nearest the pointer, `revealLevelAt`), and the slow tilt's lane on the timeline has the same two ends to drag (Keller, 4 November); if the fast cycle is too short for the wobble, the panel shows the minimum fast cycle in red. This is for real banknotes, not just the prototype), Custom angle (by tilt or by lens). The dropdown shows a ridge picture and one line per option. Vertical ridges (the Vertical effect, or a Custom lens playing only side to side) can't be printed for the sponsor: the section shows "Not supported by our sponsor, Oberthur" in the warnings' amber while they are chosen, and the picker's Vertical option says it too (Keller, 3 November). Each tilt has its own cycle; the lens angle follows from them. The presets all store their one Cycle in `cycleDeg` (Partial reveal's slow cycle is computed); only Custom reads `cycleXDeg`. Switching effect (`src/lib/switchEffect.ts`) keeps flat, band, wobble and directions, carries the fastest playing cycle into a preset (back to the default if it's over 180°), and starts Custom from exactly what the current effect gives. No preset numbers. Hidden frames are an outcome shown with an eye-off icon and ↕/↔, never a setting. Lenticular only, no microlens arrays. The Lens effect's tilt map is only a picture (it doesn't tilt banknotes): a click swaps it for the print and back (no toggle; the hover tooltip says so). The print (`src/lib/print.ts`, `src/editor/PrintView.tsx`) is the selected banknote's thread, magnified, with its real frames tiled as on the banknote and cut into strips under the ridges: strips at the ridge angle, each frame's strip as wide as its length, the frame seen flat under each ridge's middle, drawn the same way round as the tilt map. The strips seen at the current tilt stay lit. Cycle alone never changes it. Ridges (shown only with the print) sets how many ridges it draws across the thread; it and the view are remembered per browser (`src/lib/printView.ts`), not saved in projects. Only the lens lab's ridge maths came over, none of its pitch numbers or print checks.
- **Thread pattern** (`src/lib/pattern.ts`, `ThreadPattern` on `Note.pattern`): frames are full-thread artwork and sections are masks over them. Sections sit in one repeat (Tile length in the UI, 1 to 250 mm, 4 by default) that tiles the thread. **Fit** (`pattern.fit`, Keller, 3 November): new banknotes start on it, and the tile follows the thread, as long as the first image is when it fills the width, so it repeats back to back, or a square without one (`fitRepeat` in `src/lib/artwork.ts`); any change to the width, the direction or the first image refits it, its sections stretching with it (`keepFitted`, run on every project change by the store's `fitTiles`, so no editor has to remember to). A length typed or scrubbed turns Fit off, and ↺ Fit to the width (to the height on a horizontal thread) turns it back on. Banknotes from before it have no `fit` and keep their tile; along is mm from the repeat's start, across a share of the thread's width. Editing snaps to 0.5 mm along and twelfths across, and sections never overlap: drawing cuts back, moving slides until blocked, and edges on one seam move together. Mixed angles is off by default: off, every section plays the banknote's lens (a section keeps its own for when it's switched back on); on, each plays its own, and fields it leaves out take the defaults, never the banknote's. Every section's print has one strip per banknote frame at that frame's length, so flat and the cycle mean the same everywhere; a section's track picks the frame each strip shows (by frame id, a shorter story padded). A banknote without a pattern is one section over the whole thread and is drawn by exactly the old path (tested against the old renderer). Presets: Single lens, Split band, Alternating (segments), Chevron lock; they keep the banknote's flat, Cycle and directions. The rules (`src/lib/patternRules.ts`) only ever warn: every window shows each tilt wherever the print lands, one rest frame, frames only some sections show under ridges within 10° of their tilt's axis (mirrored pairs fine), one strip count (only strips set for another number of frames, as after adding or deleting one; a story that repeats frames is fine), minimum 1 mm by 1 mm less a 0.2 mm dead zone where angles meet, at most 3 ridge angles, no gaps. The sizes are placeholders until Oberthur confirms them. The print isn't registered to the banknote: the offset is a preview only (`src/lib/patternOffset.ts`), remembered per browser by banknote, never saved or undone, shown only when some section is shorter than the repeat, followed by the canvas and export; the thread editor shows the repeat from its start. With Mixed angles, playback sweeps each tilt at its fastest section's cycle (both tilts when both play and there are no moves), and the timeline follows the section selected in the thread editor, else the first. The print cuts each section at its own ridge angle with one ridge width, over two repeats where it can (at most three thread widths long); gaps print nothing.
- **Timeline:** each frame has a relative `length`, and its share of the total is its share of the cycle. Cycle (`tilt.cycleDeg`) is per banknote, with the lens. `tilt.transition` (Fade), speed, curve and the moves list are project-wide. Fade and motion controls live in the Playback settings popover; the default is 1× speed, Smooth curve; 1× takes `SWEEP_SECONDS` (about 1.9 s) a sweep each way, and joins between moves keep that pace (Keller slowed playback everywhere on 3 November, to three quarters of its first speed and then to 70% of that, 1× still reading 1×; holds and recordings keep their own time); pauses are Hold moves in the list. They are stored on each note but always edited for all notes together, and must never resize the timeline. Past one cycle the frames loop. The timeline shows one cycle with no angle ruler.
- **Frames' artwork** (`src/lib/artwork.ts`, Keller, 3 November): a frame holds nothing (the thread's background colour shows, `thread.backgroundColor`, set in the pattern panel's second section; without one the banknote shows through), one colour over the whole thread, or one image (`Frame.kind` 'none' | 'color' | 'image'; no stacking). The thread's repeat (`ThreadPattern.repeatMm`) is the one tile for the sections and every frame's artwork: an image sits once per repeat where its place puts it (`ImagePlace`: along in mm from the repeat's start, across and size as shares of the thickness, so it keeps its place on a thicker thread; absent, it fits the repeat and the thread, centred), so its copies fall one repeat apart, and one that runs past the repeat's end carries on into the next (copies are never cut at seams). There is no Image gap. Images always stay upright, even on horizontal threads. The print's offset moves the artwork with the sections. A thread nobody has drawn sections on takes its repeat from its first image when it gets one (`patternForFrames`), so it repeats back to back; that is what Fit now does for every banknote on it, and a tile set by hand keeps its length. Frames record their image's proportions (`aspect`) when it is added; banknotes from before are read once when their project opens (`useSettleArtwork` → `settleArtwork`, no undo step): an untouched thread takes its repeat from its first image plus its old gap (`thread.imageGapMm`, then dropped), its images at the repeat's start and as thick as the thread, so it looks as it did (other images of other proportions keep that repeat); one with sections keeps its repeat, its images fitted. NoteView, the thread editor, the print preview and export all lay images out with `imageBox` and `copyStarts`. Separate from the paper bridges between windows.
- **Watermark:** at most one per banknote, a sibling of the thread (`note.watermark`, `src/lib/watermark.ts`), added from the + on the banknote's row; Duplicate keeps it. One image, read only by brightness, since a watermark is paper thickness and has no colour, and it only ever gets lighter, since it is light coming through thinner paper (Keller's rules). By default the image's light parts are the thinner paper (on transparency, as far as they are light; on an opaque background, as far as they are lighter than it), so it glows where the image is light, as a photo of a watermark held to the light does; Invert (a switch under Replace, any image; `watermark.invert`, saved only when on) makes the dark parts thinner instead, so a black logo glows. Keller chose this way round on 2 November (the first lighter-only build had them the other way). The background (its edge pixels, or transparency) and whatever lies the other side of it stay plain paper (`thinness` in `src/lib/relief.ts`). An image is on transparency whenever it is cut out of it (`paperOf`): its edges mostly transparent, or a cutout that runs to its edges, such as a card with rounded corners (all four corners show through) or a shape with a hole (something shows through inside its outermost pixels); a line of half-covered pixels along an edge or two, as exports leave, isn't a cutout. Only an opaque image's background is read from its edge pixels. Keller saw an image with rounded corners lose them on 3 November: read by its edges alone, its own colour was taken for the background, so the corners cut nothing out (the ink came out empty, or only the detail inside). Levels then shape how thin that reading makes the paper (Keller asked on 2 November to control how an imported image comes out; built 3 November), three handles as in Photoshop's Levels on the slider under Auto levels: where the watermark starts (black; anything fainter stays plain paper), midtones (grey, a gamma that keeps its place between the ends as they move) and where it reaches the thinnest (white); plain paper always stays plain (`levelsCurve`). Auto, the default (no `watermark.levels`), fits them to each image as it is read (`autoLevels`): the start just above the background's speckle (4× the spread of its edge pixels, so JPEG noise stays plain paper; 0 on transparency) and the thinnest where all but 0.5% of the image reaches, so a faint scan comes up, gamma 1. Moving a handle saves `watermark.levels` and turns Auto off; switching Auto levels off keeps Auto's levels to set by hand, on again drops them. A new image, or removing it, starts on Auto again. On a black-on-white JPEG left the default way round, its compression ringing can still show faintly round the logo; Invert, which is the right reading for it, comes out clean. It is drawn as one layer colour-dodged over the design and under the thread, up to `THINNEST_GAIN` (2×) the light for the thinnest (`lightPixels`): it brightens the design in proportion, so it shows in the banknote's own colours, plain paper is unchanged and dark print stays dark, as ink blocks light. Its opacity is how much of that light comes through, so the reveal is more light, not an image fading in. On very light paper the screen has little room above the paper colour, so detail inside the glow can merge into white; only dimming the banknote when lit would fix that, which Keller ruled out. Darker, thicker parts (multiply), Hard light, Blend modes and an SVG Fill colour were all tried and removed: paper can't be coloured, and darkening reads as print. The thumbnail beside Replace shows the image in greyscale. Placed by its top-left corner in mm, its height following the image (X, Y and Width typed in the panel are kept exactly, in any unit; drags, nudges and a new watermark snap to 0.5 mm); Depth (0 to 100%) sets how strongly it shows at its clearest, tilted or held to the light. On the canvas it handles like the thread, as Keller asked: a press on it, faint or clear, picks it and a drag moves it (0.5 mm steps, once past 3 px so a click doesn't nudge it), so dragging there moves the watermark instead of tilting the banknote; with Depth 0, or in thumbnails, it takes no press. Placing works like windows, with no mode: picking the Watermark layer, pressing the watermark on the canvas, adding it or uploading its image shows the banknote flat with the watermark clear and its box to drag (styled like the window editor: solid fuchsia border with a ring; corners resize with the proportions kept, 0.5 mm steps, arrow keys nudge); a click elsewhere on the banknote, the empty canvas, Escape or another layer ends it, and Delete removes the watermark. Placing pauses playback and hides the tilt pad. Reliefs are worked out in steps (`src/lib/relief.ts`) so a drag on the levels stays live: each image's pixels once at a detail (`canvasDetail`: 1024 px on the long side, 2048 once the canvas shows it bigger than that; an image is never read past its own pixels, while an SVG is drawn at the detail itself, however small its own size, so it stays sharp when enlarged: Keller saw SVG watermarks pixelate on 3 November, read at their 80 px), then a reading per Invert (its thinness and Auto's levels, the last one showing while the next is worked out), then a light layer per levels drawn through a 256-entry table (`lightPixels`), a few of each kept. NoteView draws that layer on a canvas at the size it shows at (`reliefPixels`), scaled down smoothly so fine detail doesn't turn to grain, and export draws the same layer the same way.
- **Light:** how clearly the watermark shows (`src/lib/light.ts`). Flat in reflected light it is only a hint (`WATERMARK_FAINT`, 5% of its depth); tilting either way brings it out with no light needed, all of its depth (`WATERMARK_TILTED`) from `WATERMARK_TILT_DEG` (30°) on; held to the light it is clear even flat, which is what the light is for. Keller set this on 3 November: 30% flat was far too visible (a dollar's watermark can't be seen flat in normal light), then 2% flat with tilting held to 10% made it almost impossible to see tilted. Nothing else changes in the light: Keller was explicit that the design and the thread must look the same (no grey or monochrome filter, no dark thread, no darkened canvas). The lamp on the tilt pad, or a tap of L, holds every banknote up to the light until switched off; holding L peeks at the other light while it is down. The light fades in and out over `LIGHT_RAMP_SECONDS`. The live light is preview state (`useTilt`), not saved. Playback has a ☀ Hold to light move: flat, the light fades in, holds for its seconds and fades out; recordings keep the light too, and the pad draws the stretches played up to the light bold (a ring round flat for Hold to light). No amber anywhere for light: the app uses amber for ↔ and sky for ↕. Export matches the canvas: the watermark follows each frame's tilt and light, and the lamp left on makes it clear for the whole video (as banknotes left turned over export their backs, the dialog's summary saying · backs).
- **Magnetic ink:** Week 8's brief lists a SPARK Flow PRIME magnetic ink area (SICPA's ink whose colour shifts as the banknote tilts while a bright bar rolls across it); Keller picked it, with the continuous design check, from the security features plan on 3 November, skipping Arc-en-Ciel and Anima foil for now. At most one per banknote, a placed layer like the watermark (`note.magneticInk`, `src/lib/magneticInk.ts`), added from the + on the banknote's row; Duplicate keeps it. Its shape is one uploaded image, read as the stencil the ink is printed through (SPARK is screen printed, and the printer's magnets then turn its flakes, which is what the colours and the bar stand for), from the same pixels, background and speckle as the watermark's (`src/lib/relief.ts`) but for how much ink each part takes, not light (`inkCoverage` in `src/lib/inkMask.ts`). On an opaque background the ink is whatever is lighter or darker than it, as far as it is, past the background's speckle. Cut out of transparency, it is the shape itself, rounded corners and all, less whatever is drawn on it in another colour, as far as that stands out from the shape's own main colour (the middle brightness of its opaque pixels, past their speckle): Keller's 15 strip, magenta with its 15 drawn in the paper's cream, prints with the 15 left open and the banknote showing through, and a shape of one colour, white included, prints solid. Read by its outline alone, as it was until 6 November, the strip came out one flat bar, its 15 lost. Either way the strongest part (bar 0.5%) counts in full, so a faint scan prints solid, and soft parts stay soft, as thinner ink: Keller chose that over a hard limit at each spot, so clean art (an SVG, pure black and white, a clean cutout) comes out crisp by itself and soft art as it was drawn. Invert (`magneticInk.invert`, saved only when on) inks round the shape instead. It has no levels. Four settings and nothing else: the Flat colour; the Tilted colour it turns to as the banknote turns away, either way or both (all of it from `INK_SHIFT_DEG`, 30°, eased); the tilt its bar rolls on (↕, a level bar, or ↔, an upright one); and the bar's width as a share of the shape. The bar is white, 75% in its middle fading out to its edges, sits in the middle flat and rolls towards the nearer edge, as the thread's sheen slides, wholly off it from `INK_ROLL_DEG` (20°). How far the colour and the bar go is fixed, tuned by eye as the watermark's 30° was. The magnetism itself (a detector reading it) and SICPA's DIMENSION and CONFLUENCE variants are left out. It is drawn over the design and the watermark and under the thread, the same in the light. It is ink on the front, so it doesn't show on the back. It is placed like the watermark (picking its layer, pressing it on the canvas, adding it or uploading its image shows its fuchsia box; drags, corners and arrow keys move and size it in 0.5 mm steps, its proportions kept; Delete removes it), but placing it brings nothing out: it shows as it does at that tilt. NoteView draws its two colours and the bar in its box under a CSS mask of the shape (an alpha-only PNG made from the coverage, saved in the background, `useInkMask`, a few kept, read at the watermark's details), and the live tilt changes only the Tilted colour's opacity and the bar's transform (`ink-shift`, `ink-bar`); the export fills the same and cuts it with the same mask (`drawInk`).
- **Back** (`src/lib/back.ts`; Keller, 3 November: "we also have a backside of the design"): every banknote has a back, its own design as the front has one (`note.back`, saved once a design is set; until then, and without one, plain paper, as a front without a design is). The banknotes turn over together, as the lamp holds them all to the light: Front | Back at the top of the canvas, F (not in Thread Studio) or a Flip move in playback (see Tilt) turns them round side to side, as a page turns, in perspective over `FLIP_SECONDS` (0.5 s, eased by `turnDeg`, both in `src/lib/back.ts`, run by the tilt loop beside the light: `flipped` is the switch and `turn` how far round they are, from halfway showing the backs, `showsBack`), and each banknote's label says Back meanwhile. It is a way of looking, not saved, back to the fronts when the project closes. The back shows its background and the watermark and nothing else: the thread is on the front only (Keller), and so is magnetic ink, printed ink rather than something light passes through (Claude's call, put to Keller to change). So turned over, the timeline shows no frames even with a banknote selected, the bar staying as it is with nothing selected (Keller, 7 November); it follows the switch (`flipped`), not the turn, so the frames go as Back is pressed and come back as Front is. The watermark is in the paper, so it shows through, the other way round at the other side (`mirrored`: X from the right instead of the left, the image flipped), with the same light and tilt as on the front; on the back it can be picked, dragged, nudged and resized as on the front, its box where it shows and moving the way the pointer does, its X field reading From right. Picking the thread or magnetic ink, or anything that opens them (a scrub, Thread Studio, a window, dropped images), turns the banknotes back to the front; turning over while one is picked picks the banknote itself and ends window editing. Tilting a back turns it the way the front turns. The turn itself is part of NoteView's transform (`turnDeg`, added to its rotateY; the export's too, `withTurn`), and from halfway its face changes, the same watermark canvas staying painted. The demo's banknotes have backs, the first's showing the bird in a plain oval of its own on the right.
- **Rotate** (`src/lib/rotate.ts`; Keller, 7 November: two buttons beside Front | Back, one turning left and one right): Rotate left and Rotate right turn every banknote a quarter turn on screen, each about its own middle, as Shift+R and R do (not in Thread Studio). Like turning over, it is a way of looking, never saved or undone, upright again when the project closes: `quarterTurns` in the tilt store, counted on either way (−1, 5) so each turn plays the way it was asked, read as 0 to 3 by `quarterOf`. The canvas turns a wrapper round each banknote (`data-note-turn`, a CSS rotate over `ROTATE_SECONDS`, 0.3 s), so everything on it turns with it: thread, watermark, magnetic ink, windows and their measures, the placing box, the continuous check's neighbours. Its name stays upright over the top left of the box it shows (`turnedCorner`, in shares of the banknote, so a zoom doesn't set it gliding). The tilt stays the banknote's own: its ↕ is up and down along the banknote whichever way it shows, so the lens, the timeline, the tilt pad and playback are unchanged, and a drag on the canvas, a thread, layer or window drag, and arrow-key nudges are turned back to the banknote's axes (`unturn`, `unturnedPoint`), so it tilts or moves the way the pointer goes, as one held turned in the hand would; resize cursors swap on its side. Snapping and Fit use the box it shows (`noteBox`). A view still fitting every banknote glides to fit them turned (a live view, as a pan is, so it goes on fitting); one panned or zoomed stays where it is, and Fit takes them in again. Export follows it: each banknote is laid out on its side (`rotatedReach`) and drawn tilted about its own axes, then turned about its middle (`drawExportFrame`'s `quarter`); the dialog's summary reads · rotated 90° right, 180° or 90° left.
- **Continuous design check** (`src/lib/continuous.ts`; the brief asks that the artwork on the top and bottom edges, and on the left and right, blend into each other, and the midterm crit asked to allow 0.5 to 1 mm for cutting; Keller approved the plan's section 2 on 3 November): no new layer. A banknote whose background is an uploaded design gets a Continuous check switch on its Banknote tab, under Background (Keller named it) (`ContinuousSection` in `src/editor/DesignChecks.tsx`), saved on the banknote only while on (`note.continuous`, kept by `migrateProject` through `fitContinuous`) with its Cut tolerance (`cutMm`, ±, 1 mm by default, 0 to 5) and undone like any edit. It reads the design as it shows (cut to the banknote's proportions as `object-fit: cover` cuts it, over the paper, about 8 px per mm, `useDesign`) and compares the top edge with the bottom and the left with the right, pixel by pixel along them (`edgeBreaks`: more than 0.06 apart in OKLab with nothing that close within 0.3 mm along the other edge, so a line crossing the seam at an angle still joins; breaks under 0.25 mm are dropped, ones within 0.5 mm run together). While the banknote itself is picked (`src/editor/ContinuousView.tsx`), it has no selection outline or name label on the canvas, so nothing comes between it and its neighbours (Keller; the label, and with it dragging the banknote by its label, comes back once another part is picked or the check is off), and the canvas shows copies of the design where its neighbours sit on the print sheet, behind the banknote, as strong as it for the first 5 mm out, so the colours meet at the seam as printed, then fading out by 10 mm (at most 120 px all told; Keller found faint copies only ever showed a step at the seam, so you couldn't see whether the colour carried across), with the banknote's shadow off meanwhile; amber bars just outside both edges of a pair where they break, amber as warnings are; and the cut tolerance as a dashed line inside each edge. Drift X and Y under it preview a cut landing up to the tolerance off, either way: the design, its copies and the breaks slide the other way under the banknote, the neighbours' art coming in at the edges, while the dashed line stays where it is, as it marks where the cut can land (Keller) (NoteView's `faceShiftMm`, drawn with `DesignTiles`); never saved or undone, back to none once the tab closes, like the print offset a way of looking. All of it lies flat, so it steps back while the banknote is turned more than 2°, played or dragged, takes no clicks and is never exported. It expects the design at trim size, with no bleed. A Checks drawer at the Banknote tab's foot (for an uploaded design, closed by default, the number of checks with something to look at beside its title, built as Thread Studio's) lists, with Continuous on, At the banknote's size (how much is cut off to fit when the proportions differ), Top joins bottom and Left joins right (each break in mm from the left or the top; past four, how many and how much of the edge); and, whatever the switch, Watermark on light paper (weighted by where the watermark's light falls, through its levels; the whole box without an image) and Light paper around the thread (within 2 mm of where it shows, its windows or its whole length; the brief asks for white around it): print darker than L* 80 over more than 10% of it warns, with how dark that print is on hover. These thresholds are first guesses, to tune with Keller. Like the thread's rules, the checks only ever warn. Turned over, the switch, the canvas's neighbours and the Checks are for the back's design (`designFace`), the drawer marked Back: the watermark is checked where it shows through there, the other way round, and nothing round the thread, which is only on the front; the drift moves the back's design as it moves the front's.
- **Threads:** a banknote comes without one (`noThread`, set by New banknote; Keller, 4 November: a new banknote coming with a thread made no sense), and gets it from the Add menu like any other feature: the usual new thread, two colour frames and no windows, its lens and playback kept (`withNewThread`). Removing it, from the bin, sets `noThread` again and resets it to a new one, so nothing of it is kept or saved. Without one nothing of it shows, on the canvas, the export or the checks, the timeline shows no frames and Thread Studio can't open; images dropped on such a banknote give it its thread with them as its frames. Banknotes from before, the demo's and duplicates keep theirs. They can run vertically or horizontally, with windows switched on or off (off = continuous). New banknotes start with them off (Keller, 3 November); switching them on brings the usual windows (8 mm open every 14 mm, kept ready on the banknote), the first ready to adjust. Windows are individual start/end sections, edited only on the canvas (Keller, 4 November, after finding the panel's strip and Start/End fields bad), with no edit mode: picking a window (on the canvas, switching windows on, the Windows card's +, or a window named in a warning) starts editing, and clicking elsewhere on the banknote, the empty canvas or Escape ends it: draw, move, resize, or delete (the Delete key), snapping to 0.5 mm. Meanwhile the measurements sit on the banknote and its windows (`WindowMeasures` in `src/editor/WindowEditor.tsx`, Thread Studio's `Measure`), each a small field to scrub or type: every window's length (L, labelled Window n) on its own tile where it fits, else beside it with a bracket, along one side of the thread (left of an upright one, above a horizontal one); and for the picked window, along the other side, what lies before and after it: the gap to the next window (G) or, where there is none, the banknote's edge (From top and From bottom, Y; From left and From right, X), each in the middle of what it measures where it fits, else flush against the window (the edge only where there is no neighbour: Claude's reading of "its distance from the banknote's edge and the gaps to its neighbours", put to Keller). A length typed or scrubbed moves the window's end; a distance moves the whole window, its length kept, no further than the next window or the edge. A length with no room from its neighbours' hides, never the picked window's, and every measure hides below 2 px a mm (`MEASURE_MIN_SCALE`, about 53%), too small to read against its window; a press on a window's measure picks it. The cards keep their size while the canvas zooms live (`data-keep-size`), take presses only on themselves (round them a click on the banknote still ends editing) and are never exported. Editing pauses playback and shows the banknote flat with hidden artwork faintly visible. On the canvas, dragging a thread moves it across the banknote (X for vertical, Y for horizontal, 0.5 mm steps), and clicking a window selects it for editing. Legacy repeating patterns migrate to sections. There is no white surround.

## Data

- Everything is stored in the browser's IndexedDB (`src/lib/db.ts`), images as blobs, and nothing goes to a server. Projects therefore live in the browser they were made in. Use the Demo button on the project list to get sample content anywhere. The demo is built in code (`src/lib/demo.ts`; its artwork, the printed faces, bird portrait, flapping bird, star and bird's head, is drawn on a canvas in `src/lib/demoArt.ts` and stored under fixed ids, once a session), so it changes only with the app; the shared template in Supabase (`supabase/demo/`) is no longer read. It opens playing its playlist (only a demo with one does), and leaving it stops playback and goes back to flat. Keep Mixed angles (several sections with their own angles) out of the demo until Keller knows it can be printed; its watermark sits in almost white paper with a slight green tint, and its playlist has no Hold to light (Keller, 3 November). Its second banknote shows Partial reveal as Keller set it out: five frames up/down, three side to side, the two outer ones (only up/down shows them) special enough to notice, a small star between the big ones. Both have backs, drawn too (`DEMO_ART.backs`), the first's plain oval on the right, where the bird watermark shows through turned over. Tests can't draw on a canvas, so they mock `createDemoProject` with a plain banknote. When a feature lands, consider showing it in the demo.
- When you change a saved shape, add a migration in `migrateProject` (`src/lib/notes.ts`) so existing projects keep working. An open tab can still hold the old shape in memory until it reloads.
- Image hooks that read a module-level cache (`useImageUrl`, `useRelief`, NoteView's `useImageAspect`) work out the value while rendering and, when it was missing, re-check in their effect: another view can fill the cache between this one's render and its effect, and the React Compiler won't recompute it without a state change.
- **Display copies** (`src/lib/images.ts`; 3 November, after large uploads made tilting stutter as the browser unpacked them whole again and again): never draw an uploaded original on screen. Every view passes `useImageUrl` (or `loadImageUrl`; the print preview through `loadArtwork` and `framePx`) the device pixels it draws the image across (`devicePx`, `designPx`, `THUMB_PX`) and gets the smallest display copy at least that big (256 to 4096 px on the long side, doubling), or the original past the largest; SVGs, which draw sharp at any size, and browsers that can't run the worker, get the original. Export is the exception: it draws the originals, at the full resolution they were uploaded at (Keller, 3 November), and reads the watermark and magnetic ink from the whole image too (`exportRelief`, `exportInkMask`: up to 8192 px, an SVG at least as big as the video draws it), afresh and not kept. Copies are made off the main thread (`src/lib/imageWorker.ts`, driven by `src/lib/imageWork.ts`), JPEG for opaque images and WebP for ones that show through, and kept only in this browser's own IndexedDB store (`of-thread-display-copies`, by image id and file size), never uploaded or saved in projects, so the original stays as uploaded. A new upload starts its copies at once, and `ThreadArt` gets every frame's ready ahead (`useWarmImages`), so a tilt never comes to one late. The watermark, magnetic ink and continuous check read their pixels from a bitmap the worker shrinks from the original (`pictureOf`), never from a compressed copy. Five 4000 px frames played at 44–55 fps with freezes up to 0.6 s before; with copies, a steady 60 fps.
- Every image a banknote uses must be listed by `projectImageIds` (`src/cloud/repository.ts`), or it isn't uploaded on save or copied from the demo, and by `noteImageIds` and `copyNote` (`src/lib/store.ts`), so Duplicate gives the copy its own. A new image field goes in all three.
