# CLAUDE.md

Banknote Playground: a design tool for previewing lenticular security threads on banknotes (Oberthur Fiduciaire x ArtCenter studio). See README.md for what it does and the code layout.

The app is called Banknote Playground (renamed from Security thread playground on 3 November): page title, sign-in page, project list, package name. Production is the Vercel project `banknote-playground`, deployed from the GitHub repo KellerWang2003/banknote-playground, at banknote-playground.vercel.app. Keep of-playground.vercel.app: it serves the same deployment with no redirect, since a browser keeps its username, settings and offline copies per address and the old link has been shared. Older names stay on purpose where renaming would risk users' data for nothing they see: the Supabase table, bucket and function (`thread_playground_projects`, `thread-playground-artwork`, `thread-workspace`) and the `of-playground.*` browser storage keys (renaming those resets what users' browsers remember). The folder was renamed to match (it was `OF Security Thread Playground`), and so was the parent folder's launch config (`banknote-playground`, was `thread-playground`).

## Commands

- `npm run dev`: dev server. From the parent folder, the `banknote-playground` launch config runs it on port 5174. It answers on the Wi-Fi too, and opens a door for phones over https at its port + 1000 (`dev/phoneDoor.ts`, see Demo).
- `npm run build`: type-check (TypeScript 7) and build. Run it before every commit.
- `npm run lint`: Oxlint. `src/components/ui/**` (generated shadcn code) is ignored.

## Working with Keller

- **Branches:** the app has live users, and main deploys to them through Vercel. Do all work on the `dev` branch, or a feature branch off it, and commit and push there. Merge into main or push main only when Keller explicitly says to in that conversation. The Supabase backend is shared by every branch, so treat database, function or template changes as live too, and check with Keller first.
- Plan first. Don't write code until Keller says to build. A scope change or "let's focus on X" means update the plan, not implement it.
- He iterates by giving feedback on the running app. Commit after each round, with a message that says what changed.
- Call notes "banknotes" in the UI.
- No tutorial or hint text in the UI. Keep only what's needed, and name terse field labels in a `title` tooltip instead. Where a control is hard to grasp the first time (1 → 5, Cycle), use `Explain` (`src/editor/LensVisuals.tsx`): a hover tooltip with a small picture and one line. Two tips show by themselves, each at Keller's ask. The first thread added in a new project (banknotes come without one, see Threads) shows itself in the right panel with "You can add windows here" in a tooltip beside the Windows card (`WindowsCard`'s `tip`; 3 November), since banknotes start without windows; the next click or key anywhere ends it, and that click still does what it lands on (switching Windows on, say). And a project with no banknote, as a new one opens on its blank canvas (see Canvas), has "Start by adding a banknote here" in a tooltip beside the Banknotes list's + (`ProjectPanel`'s `addTip`; 10 November), pointing at it from over the canvas, for as long as it has none, except while New banknote is open; nothing opens by itself (New banknote did until then).

## UI rules

- Use shadcn components for every control (`npx shadcn@latest add <name>`, base-nova style, Base UI primitives). Don't hand-roll buttons, inputs, menus or dialogs. Compose them in `src/components/controls.tsx`. Keller will restyle `src/components/ui` and the tokens in `src/index.css` later.
- After adding a component, replace `from "cn"` with `from "@/lib/utils"` in the generated files.
- Shortcuts stand aside while the keyboard is busy elsewhere: in a field being typed in (each handler's `TYPING`), or while a popup shows (a dialog, a menu or a dropdown's list), which `popupOpen` answers (`src/lib/popups.ts`). Ask it rather than looking for popups in the page: Base UI leaves a dropdown's list in the page, hidden, once its trigger has had the keyboard, and counted as open (until 11 November) it left the editor's keys dead after any dropdown had been used (F, R, L, Space, ⌘Z, copying features, Thread Studio's Escape and Delete), until the panel holding it closed.
- Colour fields (`ColorField`) are Figma's too: the hex is typed, with its # or without, three digits read as shorthand once the field is left (F80 is FF8800, `typedHex`), and the swatch before it opens the app's own picker (`ColorPicker` in `src/components/ColorPicker.tsx`, its maths in `src/lib/color.ts`), a popover with a square of saturation and brightness, then the eyedropper beside a hue strip, then the colour typed in the mode picked from the menu at its start (Keller, 9 November: "input hex, input any other like color modes like RGB or HSB"): Hex, its own hex field read as the field beside the swatch is, or RGB, HSB or HSL, three small `ScrubField`s each (R, G, B 0 to 255; H 0 to 360, then S and B or S and L 0 to 100), as Figma's picker offers them. The mode is remembered per browser, as the length unit is (`useColorMode`), whichever picker it was picked in, Hex at first; the numbers read where the square and strip were set, so a grey keeps the hue it was shown with. While a picker is open, I starts the eyedropper as Figma's does (Keller, 9 November: "when a color picker is active, i should be able to just press the key I to initiate the actual color picking"), unless a text field has the keyboard: the browser's `EyeDropper`, so a click anywhere on the screen, the canvas or another window, gives the field the colour under it, the picker staying open; Escape ends a pick under way, then closes the picker. Only Chromium browsers have it (Chrome, Edge, Dia), so Safari and Firefox show no eyedropper and I does nothing there. The picker took the place of the browser's own `<input type="color">`, which on a Mac opens the system's Colors window: that takes the keyboard while it is open, so no page can hear a key.
- Number fields are Figma-style `ScrubField`s (drag the label to scrub), not sliders. Typed past its limits, a field drops the value once it is left; a `strict` length field (a banknote's size) keeps it instead, marked as an error with the limit under it (`limitErrors`), until it is fixed.
- Lengths are always mm in the code and in saves; only how they read changes (see Units below). A length field is a `LengthField` (`LengthNumberField` in a dialog), which takes and gives mm and carries the unit menu on its unit; a length in text goes through `formatLength` or `lengthIn` with the unit from `useLengthUnit` (`src/lib/units.ts`). Never write "mm" after a length by hand.
- **Visual hierarchy** (Keller asked for one set on 3 November; follow it everywhere):
  - Type, five steps in the panels: 14px (`text-sm`) for content: list rows, values in fields, inputs, menus. 13px (`text-[13px]`) for panel headings: the right panel's header, Thread Studio's part tabs and `Group` titles. 12px (`text-xs`) for labels: field labels, counts. 11px (`text-[11px]`) for the small label over each control in a side panel (`Labeled`, regular weight, always shown, as Figma's property labels: Keller wants no one guessing what T or a strip means; leave it off only where a word in or beside the control already says it) and for small headings: `Section` titles, Banknotes · n, Presets, Sections · n, the export dialog's, in sentence case. 10px (`text-[10px]`) for notes on chips and in pictures (frame numbers on clips, durations); pictures may go smaller. Only the project list and sign-in pages go larger.
  - Weight: 400 for values and body, 500 for anything interactive (buttons, tabs, rows) and small headings, 600 for headings (the right panel's header, `Group` titles, the open tab).
  - Buttons: primary (filled, the default variant) is the one main action of a panel or section: Export (in the corner bar, top right), Edit in Thread Studio above the timeline while a thread is picked, a dialog's confirm, New project, Continue. Primary buttons are pink, the Intaglio Playground's accent (#c60056, `--brand` in `src/index.css`; Keller, 7 November), so play is pink while playing, as it is filled then. The `primary` token itself stays near-black, for what is picked or pressed: selection outlines, the lamp and # toggles, the playhead, switches and the tilt pad. Secondary (`outline`) is a standalone action beside a primary or where a filled one would shout: Cancel, Replace or Upload an image, Import, presets and strips in the thread editor. Ghost (`ghost`, `IconButton`) is for toolbars and inline actions: add, duplicate, delete, undo, zoom, menus, rows. Destructive only confirms a delete in a dialog.
  - Dividers, two levels (Keller): dark, full width (`border-border`, as the `Separator` under the project name) under a panel's header and between groups or other big sections; lighter and inset with padding (`border-border/70`, a `Group`'s own `divide-y`) between the sections inside one. Panel outlines stay `border-border/70`.
  - Corners (Keller asked for one radius on 3 November): every floating panel has the same corners, 15 px (`--radius` + 6 px + the 1 px border, so `rounded-lg` controls inset 6 px sit concentric inside), set once on `Panel`; don't give a panel its own rounding. That covers the Banknotes panel, the corner bar, the right panel, the tilt pad, the playback bar, and Thread Studio's top bar, panels and zoom bar, which copies the canvas's corner bar. Controls inside keep `rounded-lg` or smaller, and small labels on a drawing (Thread Studio's measures and the window measures on the canvas, `Measure`) keep their own.
  - Fills (Keller, 4 November; one rule for all of them, 95% opaque overall, since 7 November): every grey or white surface lying right on a panel is 95% opaque as seen, so 5% of the canvas shows through it, which on the panel's 85% takes a fill of its own of 67%: number fields (`ScrubField`) and selector tracks grey (`bg-muted/67`), dropdowns (`SelectTrigger`), colour fields and outline buttons, the upload cards among them, white (`bg-background/67`); and, as Keller asked for it to be consistent everywhere, the picked banknote's block and a picked feature row in the Banknotes list, Thread Studio's picked section, the open part tab, icon buttons' and toggles' hover, switch and slider tracks (the switch's `bg-input/67`), the tilt pad, the tilt card's lamp and Back to flat, the Windows card and the timeline's track. On the canvas, with no panel under it, the + that uploads a design is 95% itself (`bg-background/95`). Fills stack: a surface shows the canvas only through what its panel lets through, (1 − 0.85) × (1 − fill), so the first 90% fill let just 1.5% through and Keller found the controls fully opaque, and 33% (10% through) was too see-through; nothing on a panel can be more see-through than the panel itself (15%), and if the panel's opacity changes, every fill must follow to keep 5%. What sits on another fill keeps its own look (a selector's picked pill, solid white on its track; hover on the picked block, `foreground/5`; the thumbnails in upload cards), and hover tints on rows (`muted/50`) and read-only value boxes (`muted/40`) stay a lighter grey, so they still read lighter than what is picked or can be typed in. Tabs and icon buttons have no box at rest and stay clear, and a button that sets its own colour keeps it (Thread Studio's tinted frame and strip buttons; the pink primary buttons and toggles pressed in `primary` stay solid). A colour field's swatch has a faint outline, so white still shows on the white fill. Selectors (`Segmented`) are Figma's: a grey track as tall as a field, the picked option a white raised pill in dark text, the others grey text (the picked option used to be only a shade darker than the rest).
  - Thread Studio's part tabs carry their icons and scroll sideways once they don't fit (`TabStrip`: an edge fades while more lie beyond it, and the open tab scrolls into sight). The zoom percentage shows only in the canvas's corner bar, between − and +, where a click goes to 100%, about true size at the screen's 96 px an inch (Keller took it out on 3 November, as nothing said what 100% was, and wanted it back on 4 November); Thread Studio's zoom bar has none.
- New UI copies what is already there rather than inventing sizes: match the nearest existing row, field, button or editor (text size, height, padding, radius, selected and hover colours). The palette is neutral, but for the app's pink (`--brand`; Keller, 7 November), which only primary buttons (see Buttons), the sign-in page's banknote mark and the account menu's avatar wear; the few accent colours already mean something: sky = ↕, amber = ↔, fuchsia = editing on the canvas (windows, the watermark's and magnetic ink's boxes), rose = snap guides. On a phone a project opens in Demo (see Demo). Sign-in is a single username field with Continue.

## Product decisions

- It's a general tool, not tied to the Flight notes: a project is created with just a name, New banknote asks only for a name and size, and no banknote has a colour of its own: every one is printed on the same very light grey paper (`PAPER` in `src/lib/back.ts`), which shows wherever a side has no design and through a design's transparent parts (Keller, 4 November: "they have to use the design"; a colour saved before stays in the save, unshown, in case it comes back), and banknotes can be any size from 20 mm to 2 m (`NOTE_SIZE`; Keller, 3 November: large ones run to 2000 mm, where it had stopped at 250). There are no built-in denomination presets. A size typed past a limit shows an error under its field, in the right panel and New banknote: the field outlined in red and the limit under it in the unit picked (Max 2000 mm, Min 20 mm; over the maximum as soon as it is typed, under the minimum once Enter is pressed or the field is left, since typing 150 passes 1 and 15). Nothing past a limit is taken, and what typing took on the way (25 and 250 on the way to 2500) goes back; Enter and leaving keep it in the field to be fixed, and New banknote adds nothing until it is. The canvas zooms out to 0.02 so a few 2 m banknotes fit side by side (its dots spread to 500 mm apart); export and the watermark's light layer are drawn at capped sizes, and a 2 m square banknote played at full zoom kept 60 fps.
- **Square corners** (Keller, 9 November: "banknotes shouldn't have corner radius at all", and exports above all): a banknote is a plain rectangle wherever it shows, with no corner radius: NoteView's box and the canvas's outline round it (`data-note-body`), the skeletons (`NoteSkeleton`), Realistic, the thumbnails, and the export renderer's cut (`drawFace`), so every video frame and still image, front or back, has the paper or the design in its corners. They had 1.5 mm until then. Panels and controls keep their rounding (see Corners under UI rules).
- **Units** (`src/lib/units.ts`): Keller asked for units beyond metric (3 November). mm, cm, in and pt, mm the default for everyone (no locale guessing); px is left out, since it has no physical size without a ppi. One pick for the whole app, made from the menu on the unit of any length field (the right panel, New banknote), remembered per browser like the panel width, never saved in a project or undone, so switching never changes a value. Each unit reads to its own decimals (mm 0.01, cm and in 0.001, pt 0.1), and the banknote labels on the canvas, the window measures, screen-reader labels and the Checks follow it. Typed values are kept exactly (to a millionth of a mm), and a unit typed after the number (6.14in, 6.14", 15.6cm, 442pt) converts without switching. Scrubbing and the arrow keys (Shift for ten steps) step the largest round number (1, 2 or 5 of a power of ten) of the unit that isn't coarser than the field's mm step: 0.5 mm steps 0.05 cm, 0.01 in or 1 pt, Offset's 0.1 mm 0.01 cm, 0.002 in or 0.2 pt. Canvas and Thread Studio drags keep their mm grid in every unit (0.5 mm, a frame's image 0.1 mm; gaps fill cell by cell on it), so a dragged window can read 0.512 in. Limits stay in mm, and the number shown at a limit can be typed (a banknote's 20 to 2000 mm reads 0.787 to 78.74 in). Thread Studio's fields are `LengthField`s too: L and W (H) beside the thread, and the picked frame image's X, Y and W (0.1 mm steps: 0.01 cm, 0.002 in or 0.2 pt).
- **Frames:** 2 to 5 per banknote. Lenticular optics are not simulated: frames are artwork shown in turn as you tilt.
- **Tilt:** flat sits at the middle of the middle frame by default (frame 3 of 5, frame 2 of 4), so one tilt direction plays on towards the last frame and the other back towards frame 1. Flat is set with the pin on the frame strip in the thread editor's Lens (`FlatStrip`), snapping to half-frame steps (`tilt.flatAt` as a number; 'start' from older saves = 0); the timeline shows it read-only. Hidden frames are always the ones farthest from flat, so moving flat moves them. "1 → 5" sets whether frames run top to bottom (default for new projects; older projects stay bottom to top) or bottom to top, and left to right (default) or right to left. Both live in the small panel off the ⋯ on the Lens title (`LensMenu`, a popover, as two selectors), since they rarely change, with Partial reveal's Wobble under them. Tilt goes to ±90° (`TILT_LIMIT`, edge-on), not a setting: it limits manual tilt and playback (`SWEEP_MAX`) and decides hidden frames. Light and shade on the banknote still scale to full at 60° (`SHADE_DEG`). `tilt.viewDeg` from older saves is ignored. Playback is a project-wide list of moves played in order and looped (`src/lib/moves.ts`, edited in the Playback popover): preset moves (↕ Up/down, ↔ Side to side, Diagonal, Circle) go out from flat and back (up/down and side can start from any angle instead, e.g. swing −12° ↔ +12° without returning to flat; every move starts from flat and returns to flat before the next), by default through one full Cycle on each tilt they use; ⏸ Hold stays flat for its seconds (1 s by default, at 1× and scaled by speed, as ☀ Hold to light's are), so it pauses wherever it sits in the playlist, once the move before it has come back, and nothing else pauses (Keller, 3 November: it replaced Motion's Hold, which paused at full tilt and at flat after every move; `tilt.holdSeconds` from older saves is dropped on load); ⇄ Flip (Keller, 4 November) stays flat while every banknote turns over to its other side, exactly as F does: the tilt loop flips the same switch as each Flip begins (`plan.flips`, `flipsBetween`), so Front | Back follows it and turning over to the backs picks the banknote itself, taking `FLIP_SECONDS` at 1×, scaled by speed as every move is (`plan.flipSeconds`; while playing, F turns at that pace too). Each Flip turns to the other side, so after a pass with an odd number of them the next plays on the other side. Not in Thread Studio, where F does nothing either: there the Flip waits flat (`useTiltLoop`'s `turnsOver`, the canvas's `inStudio`). Export follows it (`turnAt`, `playbackTurns`): it loads both sides, adds the turn to the side tilt as NoteView does (`withTurn`), lays the banknotes out with room for the near edge as they come round edge-on, and plays a playlist that leaves them on their other side twice a loop, so a video ends, and a GIF comes round, on the side it began; a video starts on the side picked in its Side, which starts on the backs when they are turned over; a recording (Record a move, the last row of Playback settings' list of moves, which closes the popover, opens the tilt pad and arms it, its ring red, so the next drag on it records; Escape cancels, ahead of any other Escape) is saved to the project's Recordings and becomes the whole playlist on its own; it plays in its own time joined to flat. The Playback settings popover has one plain list of moves on the left (presets, then recordings, then Record a move; click to add to the playlist, recordings can be deleted), the Playlist on the right (reorder, remove, per-move ↕/↔ reach or a hold's seconds), and Motion (speed, curve, fade, in one row) under it. The pad draws the path. Live playback and export read the same plan. Projects without a list play the default playlist, on the tilt the old Tilt setting chose (up/down unless set): a default move (`default-` id, no angles set) glides out a full Cycle and sweeps back to flat, the way 1 → 5 runs, so it stops on the rest frame: 30° → 0° up/down on a new banknote (Keller, 3 November; it had gone 0° → −30° and back). Editing the list keeps it, following the Cycle, until its angles are set; deleting the last recording brings it back. An Up/down or Side to side added from the list swings across the Cycle centred on flat instead. The timeline starts at 0° too. Tilting must read as up vs down (and left vs right), using a strong per-note perspective.
- **Lens effects:** one lens per banknote (`src/lib/lens.ts`), or one per thread section with Mixed angles: the effect, Cycle, flat, band, wobble and 1 → 5 directions are edited for the selected banknote (or section) only (a new banknote starts from the last one's); playback and the tilt pad follow the selected banknote, or the first. Presets Up/down, Side to side, Both ways, Reveal on one tilt, Custom (by tilt or by lens), named by their ridges: Horizontal (plays on up/down), Vertical (side to side), Diagonal 45° (same cycle on both tilts), Partial reveal on one tilt (one tilt plays every frame, the other never shows the outer ones at any tilt up to 90° (`HIDE_LIMIT`), even with the hand drifting `Wobble` degrees (default 1°, set in the Lens title's ⋯ panel; Keller, 4 November: at the old 5° the demo's side tilt changed frame only past about 68°, now from about 34°, and banknotes that never set their own moved with the default) onto the fast tilt: the slow cycle is computed and the hidden count follows from it, never typed: the strip shows the slow tilt's reach as a band whose ends you drag to hide more or fewer frames (`revealLevel`, a step inwards from the widest, the one nearest the pointer, `revealLevelAt`), and the slow tilt's lane on the timeline has the same two ends to drag (Keller, 4 November); if the fast cycle is too short for the wobble, the panel shows the minimum fast cycle in red. This is for real banknotes, not just the prototype), Custom angle (by tilt or by lens). The dropdown shows a ridge picture and one line per option. Vertical ridges (the Vertical effect, or a Custom lens playing only side to side) can't be printed for the sponsor: the section shows "Not supported by our sponsor, Oberthur" in the warnings' amber while they are chosen, and the picker's Vertical option says it too (Keller, 3 November). - **Thread pattern** (`src/lib/pattern.ts`, `ThreadPattern` on `Note.pattern`): frames are full-thread artwork and sections are masks over them. Sections sit in one repeat (Tile length in the UI, 1 to 250 mm, 4 by default) that tiles the thread. **Fit** (`pattern.fit`, Keller, 3 November): new banknotes start on it, and the tile follows the thread, as long as the first image is when it fills the width, so it repeats back to back, or a square without one (`fitRepeat` in `src/lib/artwork.ts`); any change to the width, the direction or the first image refits it, its sections stretching with it (`keepFitted`, run on every project change by the store's `fitTiles`, so no editor has to remember to). A length typed or scrubbed turns Fit off, and ↺ Fit to the width (to the height on a horizontal thread) turns it back on. Banknotes from before it have no `fit` and keep their tile; along is mm from the repeat's start, across a share of the thread's width. Editing snaps to 0.5 mm along and twelfths across, and sections never overlap: drawing cuts back, moving slides until blocked, and edges on one seam move together. Mixed angles is off by default: off, every section plays the banknote's lens (a section keeps its own for when it's switched back on); on, each plays its own, and fields it leaves out take the defaults, never the banknote's. Every section's print has one strip per banknote frame at that frame's length, so flat and the cycle mean the same everywhere; a section's track picks the frame each strip shows (by frame id, a shorter story padded). A banknote without a pattern is one section over the whole thread and is drawn by exactly the old path (tested against the old renderer). Presets: Single lens, Split band, Alternating (segments), Chevron lock; they keep the banknote's flat, Cycle and directions. The rules (`src/lib/patternRules.ts`) only ever warn: every window shows each tilt wherever the print lands, one rest frame, frames only some sections show under ridges within 10° of their tilt's axis (mirrored pairs fine), one strip count (only strips set for another number of frames, as after adding or deleting one; a story that repeats frames is fine), minimum 1 mm by 1 mm less a 0.2 mm dead zone where angles meet, at most 3 ridge angles, no gaps. The sizes are placeholders until Oberthur confirms them. The print isn't registered to the banknote: the offset is a preview only (`src/lib/patternOffset.ts`), remembered per browser by banknote, never saved or undone, shown only when some section is shorter than the repeat, followed by the canvas and export; the thread editor shows the repeat from its start. With Mixed angles, playback sweeps each tilt at its fastest section's cycle (both tilts when both play and there are no moves), and the timeline follows the section selected in the thread editor, else the first. The print cuts each section at its own ridge angle with one ridge width, over two repeats where it can (at most three thread widths long); gaps print nothing.
- **Timeline:** each frame has a relative `length`, and its share of the total is its share of the cycle. Fade and motion controls live in the Playback settings popover; the default is 1× speed, Smooth curve; 1× takes `SWEEP_SECONDS` (about 1.9 s) a sweep each way, and joins between moves keep that pace (Keller slowed playback everywhere on 3 November, to three quarters of its first speed and then to 70% of that, 1× still reading 1×; holds and recordings keep their own time); pauses are Hold moves in the list. - **Frames' artwork** (`src/lib/artwork.ts`, Keller, 3 November): a frame holds nothing (the thread's background colour shows, `thread.backgroundColor`, set in the pattern panel's second section; without one the banknote shows through), one colour over the whole thread, or one image (`Frame.kind` 'none' | 'color' | 'image'; no stacking). The thread's repeat (`ThreadPattern.repeatMm`) is the one tile for the sections and every frame's artwork: an image sits once per repeat where its place puts it (`ImagePlace`: along in mm from the repeat's start, across and size as shares of the thickness, so it keeps its place on a thicker thread; absent, it fits the repeat and the thread, centred), so its copies fall one repeat apart, and one that runs past the repeat's end carries on into the next (copies are never cut at seams). There is no Image gap. Images always stay upright, even on horizontal threads. The print's offset moves the artwork with the sections. A thread nobody has drawn sections on takes its repeat from its first image when it gets one (`patternForFrames`), so it repeats back to back; that is what Fit now does for every banknote on it, and a tile set by hand keeps its length. - **Watermark:** any number per banknote (see Several of a kind), the first a sibling of the thread (`note.watermark`, `src/lib/watermark.ts`), added from the + on the banknote's row; Duplicate keeps it. One image, read only by brightness, since a watermark is paper thickness and has no colour, and it only ever gets lighter, since it is light coming through thinner paper (Keller's rules). By default the image's light parts are the thinner paper (on transparency, as far as they are light; on an opaque background, as far as they are lighter than it), so it glows where the image is light, as a photo of a watermark held to the light does; Invert (a switch under Replace, any image; `watermark.invert`, saved only when on) makes the dark parts thinner instead, so a black logo glows. Keller chose this way round on 2 November (the first lighter-only build had them the other way). The background (its edge pixels, or transparency) and whatever lies the other side of it stay plain paper (`thinness` in `src/lib/relief.ts`). An image is on transparency whenever it is cut out of it (`paperOf`): its edges mostly transparent, or a cutout that runs to its edges, such as a card with rounded corners (all four corners show through) or a shape with a hole (something shows through inside its outermost pixels); a line of half-covered pixels along an edge or two, as exports leave, isn't a cutout. Only an opaque image's background is read from its edge pixels. Keller saw an image with rounded corners lose them on 3 November: read by its edges alone, its own colour was taken for the background, so the corners cut nothing out (the ink came out empty, or only the detail inside). Levels then shape how thin that reading makes the paper (Keller asked on 2 November to control how an imported image comes out; built 3 November), three handles as in Photoshop's Levels on the slider under Auto levels: where the watermark starts (black; anything fainter stays plain paper), midtones (grey, a gamma that keeps its place between the ends as they move) and where it reaches the thinnest (white); plain paper always stays plain (`levelsCurve`). Auto, the default (no `watermark.levels`), fits them to each image as it is read (`autoLevels`): the start just above the background's speckle (4× the spread of its edge pixels, so JPEG noise stays plain paper; 0 on transparency) and the thinnest where all but 0.5% of the image reaches, so a faint scan comes up, gamma 1. Moving a handle saves `watermark.levels` and turns Auto off; switching Auto levels off keeps Auto's levels to set by hand, on again drops them. A new image, or removing it, starts on Auto again. On a black-on-white JPEG left the default way round, its compression ringing can still show faintly round the logo; Invert, which is the right reading for it, comes out clean. It is drawn as one layer colour-dodged over the design and under the thread, up to `THINNEST_GAIN` (2×) the light for the thinnest (`lightPixels`): it brightens the design in proportion, so it shows in the banknote's own colours, plain paper is unchanged and dark print stays dark, as ink blocks light. Its opacity is how much of that light comes through, so the reveal is more light, not an image fading in. On very light paper the screen has little room above the paper colour, so detail inside the glow can merge into white; only dimming the banknote when lit would fix that, which Keller ruled out. Darker, thicker parts (multiply), Hard light, Blend modes and an SVG Fill colour were all tried and removed: paper can't be coloured, and darkening reads as print. The thumbnail beside Replace shows the image in greyscale. Placed by its top-left corner in mm, its height following the image (X, Y and Width typed in the panel are kept exactly, in any unit; drags, nudges and a new watermark snap to 0.5 mm); Depth (0 to 100%) sets how strongly it shows at its clearest, tilted or held to the light. On the canvas it handles like the thread, as Keller asked: a press on it, faint or clear, picks it and a drag moves it (0.5 mm steps, once past 3 px so a click doesn't nudge it), so dragging there moves the watermark instead of tilting the banknote; with Depth 0, or in thumbnails, it takes no press. Placing works like windows, with no mode: picking the Watermark layer, pressing the watermark on the canvas, adding it or uploading its image shows the banknote flat with the watermark clear and its box to drag (styled like the window editor: solid fuchsia border with a ring; corners resize with the proportions kept, and so does a drag anywhere along the border, 5 px either way of it (`SIDE_ZONE_PX`, `data-side`; Keller, 9 November: a drag on the border only moved the box), the side across from it staying put and the box centred along it; 0.5 mm steps, arrow keys nudge); a click elsewhere on the banknote, the empty canvas, Escape or another layer ends it, and Delete removes the watermark. Placing pauses playback; the tilt card stays (see Bottom left). Reliefs are worked out in steps (`src/lib/relief.ts`) so a drag on the levels stays live: each image's pixels once at a detail (`canvasDetail`: 1024 px on the long side, 2048 once the canvas shows it bigger than that; an image is never read past its own pixels, while an SVG is drawn at the detail itself, however small its own size, so it stays sharp when enlarged: Keller saw SVG watermarks pixelate on 3 November, read at their 80 px), then a reading per Invert (its thinness and Auto's levels, the last one showing while the next is worked out), then a light layer per levels drawn through a 256-entry table (`lightPixels`), a few of each kept. NoteView draws that layer on a canvas at the size it shows at (`reliefPixels`), scaled down smoothly so fine detail doesn't turn to grain, and export draws the same layer the same way.
- **Light:** how clearly the watermark shows (`src/lib/light.ts`). Flat in reflected light it is only a hint (`WATERMARK_FAINT`, 5% of its depth); tilting either way brings it out with no light needed, all of its depth (`WATERMARK_TILTED`) from `WATERMARK_TILT_DEG` (30°) on; held to the light it is clear even flat, which is what the light is for. Keller set this on 3 November: 30% flat was far too visible (a dollar's watermark can't be seen flat in normal light), then 2% flat with tilting held to 10% made it almost impossible to see tilted. Nothing else changes in the light: Keller was explicit that the design and the thread must look the same (no grey or monochrome filter, no dark thread, no darkened canvas). The lamp on the tilt pad, or a tap of L, holds every banknote up to the light until switched off; holding L peeks at the other light while it is down. The light fades in and out over `LIGHT_RAMP_SECONDS`. The live light is preview state (`useTilt`), not saved. Playback has a ☀ Hold to light move: flat, the light fades in, holds for its seconds and fades out; recordings keep the light too, and the pad draws the stretches played up to the light bold (a ring round flat for Hold to light). No amber anywhere for light: the app uses amber for ↔ and sky for ↕. Export matches the canvas: the watermark follows each frame's tilt and light, and the lamp left on makes it clear for the whole video (as banknotes left turned over start the Export dialog's Side on Back).
- **Magnetic ink:** Week 8's brief lists a SPARK Flow PRIME magnetic ink area (SICPA's ink whose colour shifts as the banknote tilts while a bright bar rolls across it); Keller picked it, with the continuous design check, from the security features plan on 3 November, skipping Arc-en-Ciel (built 8 November, below) and Anima foil for now. At most one per banknote, a placed layer like the watermark (`note.magneticInk`, `src/lib/magneticInk.ts`), added from the + on the banknote's row; Duplicate keeps it. Its shape is one uploaded image, read as the stencil the ink is printed through (SPARK is screen printed, and the printer's magnets then turn its flakes, which is what the colours and the bar stand for), from the same pixels, background and speckle as the watermark's (`src/lib/relief.ts`) but for how much ink each part takes, not light (`inkCoverage` in `src/lib/inkMask.ts`). On an opaque background the ink is whatever is lighter or darker than it, as far as it is, past the background's speckle. Cut out of transparency, it is the shape itself, rounded corners and all, less whatever is drawn on it in another colour, as far as that stands out from the shape's own main colour (the middle brightness of its opaque pixels, past their speckle): Keller's 15 strip, magenta with its 15 drawn in the paper's cream, prints with the 15 left open and the banknote showing through, and a shape of one colour, white included, prints solid. Read by its outline alone, as it was until 6 November, the strip came out one flat bar, its 15 lost. Either way the strongest part (bar 0.5%) counts in full, so a faint scan prints solid, and soft parts stay soft, as thinner ink: Keller chose that over a hard limit at each spot, so clean art (an SVG, pure black and white, a clean cutout) comes out crisp by itself and soft art as it was drawn. Invert (`magneticInk.invert`, saved only when on) inks round the shape instead. It has no levels. Four settings for its look and nothing else, besides Realistic (below): the Flat colour; the Tilted colour it turns to as the banknote turns away, either way or both (all of it from `INK_SHIFT_DEG`, 30°, eased); the tilt its bar rolls on (↕, a level bar, or ↔, an upright one); and the bar's width as a share of the shape. The bar is white, 75% in its middle fading out to its edges, sits in the middle flat and rolls towards the nearer edge, as the thread's sheen slides, wholly off it from `INK_ROLL_DEG` (20°). How far the colour and the bar go is fixed, tuned by eye as the watermark's 30° was. The magnetism itself (a detector reading it) and SICPA's DIMENSION and CONFLUENCE variants are left out. It is drawn over the design and the watermark and under the thread, the same in the light. It is ink on the front, so it doesn't show on the back. It is placed like the watermark (picking its layer, pressing it on the canvas, adding it or uploading its image shows its fuchsia box; drags, corners, its border and arrow keys move and size it in 0.5 mm steps, its proportions kept; Delete removes it), but placing it brings nothing out: it shows as it does at that tilt. NoteView draws its two colours and the bar in its box under a CSS mask of the shape (an alpha-only PNG made from the coverage, saved in the background, `useInkMask`, a few kept, read at the watermark's details), and the live tilt changes only the Tilted colour's opacity and the bar's transform (`ink-shift`, `ink-bar`); the export fills the same and cuts it with the same mask (`drawInk`). **Realistic** (Keller, 7 November, after a comparison page of today's look, a tuned one and this; he wanted none of the tuned look, but its glow round the bar and its sparkle): with Realistic on (the toggle beside the lamp, for every banknote, see Realistic below; until 9 November a switch under Bar width, saved on the ink) the same ink is lit as metal flakes (`src/lib/realisticInk.ts`) from the same settings, no new ones: the magnet curves the flakes across the shape the way the bar rolls, just enough that the lamp's reflection rolls off by `INK_ROLL_DEG` as the flat bar does (`flakeEdge`), Bar width sets how wide that reflection's bright core is (as wide as the flat bar, `lampLobe`) with a soft glow round it, and each flake shows its thin film's colour at the angle it is seen at, from Flat square-on to Tilted from 45° (`filmShift`, the hue the shorter way round in OKLCH), so the colour differs across the shape; a per-pixel grain and stray flakes that glint as it turns give the sparkle. Keller found that first look too flashy, reflective and sparkly (9 November), so it is toned down a little: the lamp's reflection is dimmer and keeps more of the ink's colour where it went almost white (`LAMP_POWER`, `HIGHLIGHT_WHITE`), and the glints are fewer and dimmer over a finer grain, the bar and its glow rolling as before. One light, a lamp hanging over the viewer's head, 20° above their line of sight to the banknote's middle (`LAMP_HEIGHT_DEG`; Keller, 8 November: lit from above, as more realistic, after it first hung just above the eye; straight above the eye, as a lamp further off would rest each upright bar off its middle), and the magnet sets the flakes to face that viewer (`flakeRest`), so wherever the ink sits on the banknote its bar rests the same way: flat, towards the top of the ink, where the flakes face halfway between the lamp and the eye; with the top tipped back 10°, in the middle, as bright as in the banknote's middle, and rolling off either edge at the same tilt from there; an upright bar shows only near that tip, the lamp being above it rather than in its curve (square-on flakes, as first built, rested it off towards the banknote's middle and left an ink off to the side only the bar's glow: a new ink sits low on the right, and Keller's 15 strip right of the middle); the lamp stays where it is as the banknotes rotate on screen or turn over (both turn the ink from it), and holding to the light leaves the ink as it was. The numbers are tuned by eye on Keller's 15 strip and are not settings. Every pixel is shaded on the GPU by one shared WebGL renderer (`src/lib/inkRenderer.ts`; browsers allow only a few contexts): NoteView gives the ink a canvas of its own in its box, as many pixels as it shows with (`inkPixels`), lit again only when the tilt, the turn, the rotation or the zoom changes (`paintLitInk`), and the export lights it the same way into the banknote's face (`drawLitInk`, its grain a pixel a cell up to 1080p). Each drawing is made in the renderer's canvas's bottom-left corner, all of the canvas cleared first (`drawIn`): the canvas only grows, so a larger drawing made earlier would still be past its top and right, and copying a drawing out scaled or off the pixel grid, as an export does, takes in a little of the pixels just past its edges. Without WebGL it keeps the flat look, on the canvas and in exports. Foil and intaglio are to get a Realistic mode of their own once they are built; Arc-en-Ciel has one, sharing this lamp (below).
- **Arc-en-Ciel** (`note.arcEnCiel`, `src/lib/arcEnCiel.ts`; Keller said build it on 8 November, from that day's plan doc: Oberthur's brief requires it on the front and the finals lacked it): Oberthur's colour bands, an offset line screen in at least three colours embossed blind by an intaglio plate in register with it, so that tilted across the ridges the slopes facing the eye win and the bands seem to slide. At most one per banknote, the fourth placed layer, drawn between the watermark and magnetic ink (`PLACED_LAYERS` is the draw order), on the front only (`onFront`); Duplicate keeps it. Step 1 (built 8 November) is the flat look and the slide; step 2 is Realistic (built the same night, below). Every placed layer's panel now reads position first, then the image, then its settings (Keller, 8 November): From left, From top and Width; Image and Invert; then Bands from, Colours, and Band width beside Ridge angle; Edge last. Its shape is one image read as magnetic ink's is (`inkCoverage`, the same mask), and a new one starts as a black disc (`standIns.ts`). Keller wanted any design to work without per-petal controls (8 November: "our design might not have a petal"), so the bands come from the shape itself: Edge (inward from each separate shape's edge, so each petal of a flower gets its own rings, as every pixel goes by the edge nearest it), Holes (outward from holes, paper the shape closes round, corners included; greyed out without any), or Point and Line, placed as handles on the canvas (spatial choices are handles, not fields). Edge's and Holes' distances are an exact Euclidean distance transform (`bandMap.ts`, Felzenszwalb and Huttenlocher) of the shape at up to `MAP_PX` (512) px, padded with paper, rounded deeper in (Keller, 9 November: the tips and seams looked too sharp to be printed): each pixel's distance is measured through a Gaussian `ARC_ROUNDING` (0.55) of it wide and turned back through the normal curve (`roundedField`, the Gaussians 1.4 times wider each, on coarser grids as they widen), so a straight edge stays exact, rings near an edge follow it, a corner's deeper rings round off to about half their depth and a narrow stretch's middle loses a little depth with no flat top; worked out once per image and Invert and kept (a few tenths of a second at 512 px); Point's and Line's are worked out per pixel (Line is a Catmull-Rom curve through its points, signed so the bands carry on across it, running straight on past its ends). Colours are a list of three or four (Oberthur's minimum is three) with grips to reorder (Keller: "a list format with like handles on the left"), in the order the bands run from where they start, repeating, each blending into the next over its last 30% (`BAND_BLEND`), mixed in linear light. Band width is 0.3 to 5 mm (1 mm new). The slide is fixed, tuned by eye, not a setting (no physics knobs): half a band each way by 20° across the ridges (`bandSlide`), which run at any angle (`angleDeg`, −90° to 90° from the banknote's horizontal, rising to the right as it grows; Keller, 9 November, in place of Moves on's ↕ or ↔, which older saves read as 0° and −90°): the tilt across them is the up/down tilt × cos θ − the side tilt × sin θ, so level ridges slide outward as the top tips away and upright ones at −90° as the right side turns away; rotating the banknotes on screen doesn't change it. Bands too fine for the pixels fade to their colours' average (`BAND_BLUR`) instead of shimmering. It is drawn on the GPU by one more program in `inkRenderer.ts`'s shared context (the map uploaded as 16 bits in two bytes, Point and Line worked out in the shader); NoteView paints a canvas of its own in its box only when the bands move, and without WebGL it is drawn at rest on the CPU (`bandsByHand`). The export draws it the same way (`drawArc`). The shape's mask is looked up for every pixel of the drawing and left out past the box: the GPU shades pixels in 2 × 2 blocks and picks the mask's mipmap from how far apart a block's lookups are, and looked up only within the box (until 9 November), a block over the drawing's top or right edge (an odd number of pixels across) read a blurred mipmap on Keller's Mac, a line along the box at some zooms. Its handles (`ArcHandles.tsx`, over the placing box while it is placed): fuchsia dots for points and Line's ends, hollow ones for bends; drag a dot, or the line to move it whole; a double-click in the box adds a point (up to `ARC_POINTS`), on the line bends it (up to `ARC_LINE_POINTS`); a picked dot's Delete takes it out, caught before the editor's Delete, never the last point or Line's ends; every spot stays within a box's size of it (`ARC_REACH`). Whatever the bands start from, a dial over the box turns the ridges (`RidgeDial`): a dashed fuchsia line through its middle along them, edge to edge, with a pill-shaped knob towards each end; drag either round the middle (whole degrees, 15° with Shift), or pick one for the arrow keys (a degree, 15° with Shift); past upright it carries on round (`ridgeAngle`). **Realistic** (Keller, 8 November: "we also need a realistic mode for this as well"; planned in that night's doc with stills from a numpy model, then "OK go ahead" with Claude's three picks): with Realistic on (the toggle beside the lamp, see Realistic below; until 9 November a switch last on the tab, saved on Arc-en-Ciel) it draws the embossed ridges themselves from the same settings, no new ones. Ridges at the layer's angle `ARC_RIDGE_MM` (0.4) apart, until Oberthur says how fine their plates go, printed as Oberthur's brochure shows (Keller, 9 November, sending it: Realistic still looked off; he picked "Like the brochure" of three looks drawn with the numpy model): every ridge carries all the colours as fine lines, one each, in order across it, shifted a line on for every band the design moves on (`screenAt` in the shader), so flat every ridge shows them all and the design nearly hides, and tilted the slopes facing the eye show half the lines each and the design comes out as soft rings, the other half tilted the other way (as first built each slope carried one colour, half a band either side, which left the design showing flat). Each spot takes the line printed where it sees the paper (found from how fast the bands move on across the ridges). Keller found the first look "too precise and too computer" (9 November), so the print is ink on paper (`ARC_PRINT`; he picked the deepest of three softer reliefs drawn with the numpy model): each line spreads 0.022 mm into the next where they meet, along a slightly ragged edge; the print sits up to 6% of a ridge out of register with the ridges, varying over the shape; the ridges wander 0.02 mm off straight; the ink is a little uneven and dulled 5% towards a grey of the paper; and the paper is grainy and cockled 1.5°. Each unevenness is hashed value noise over the paper in the shader (`paperNoise`); what is finer than a pixel fades out (`showing`), and the finest is left out without high precision. Tilting across the ridges shifts where each crest shows on screen (`arcLight`'s `share`, tan θ ÷ tan 20°), so the slopes facing the eye take more of each ridge until by `ARC_SLIDE_DEG` only they show. Light: magnetic ink's lamp, `LAMP_HEIGHT_DEG` over the eye, staying put as the banknotes rotate (turning over turns the ridges from it, as the ink), softened by the room's light from all round (Keller, 9 November: real light isn't direct, and the lamp cast shadows too harsh; he picked Soft light of two drawn in the app, `ARC_LIGHT` room 0.55 and lamp 0.45, wrapping 0.6, where it was 0.25, 0.75 and 0.25), on round ridges, steepest down in the grooves (`ARC_RIDGE_SLOPE_DEG`, 52°) and flat along the crests, wrap-Lambert, measured so a ridge seen flat averages as much light as flat paper (`ARC_MEAN_LIGHT`; nothing else on the banknote is lit): the slope facing the lamp is a little brighter than paper and the other a little darker (first built, the light stopped at paper's, which flattened it), with a faint shadow down each groove (`ARC_GROOVE`, 20% darker at the bottom, was 45%) and a soft, broad sheen (`ARC_SHEEN`, 0.07 to the power 10, was 0.14 to 24), strongest on the crests with the top tipped back 10°; tuned by eye, not settings. **White edge** (Keller, 9 November: whether to have the white emboss round the shape, and how wide, should be a setting): a switch last on the tab, labelled Edge, off by default, with Edge width and Edge colour under it while on (`arcEnCiel.edgeMm`, 0.5 to 3 mm, 1 mm when first switched on, `ARC_EDGE`; saved only when on): bare paper round the shape, as the brochure shows, its holes and bays too where they are as narrow, covering whatever is printed beneath: flat in the plain look, and with Realistic on embossed with the same ridges and lit the same way. Until then it came with Realistic, always 1 mm, drawn as light and shade over the print beneath, which read as a grey haze over mid-tone designs (and before 9 November it filled the shape's convex hull). `outlineField` in `bandMap.ts` is the exact distance from the shape (from half coverage) over the image and 40% of its longest side past it all round (`pad`), kept with the shape's maps, which the edge loads whatever the bands start from (`needsShape`); the canvas and the export draw it `embossOutset` past the box all round (as wide as it is set, less on a box under about 7.5 mm, so the drawing's own edge never cuts it; `BandLook.outset`, the shader's `uOutset`), NoteView's canvas reaching past the box without taking presses. Point and Line draw at once and the edge joins them when ready. On the GPU it is the bands program's lit path (`uLit`): `ARC_RIDGE_SAMPLES` (6) spots across each pixel, half as wide again as it, each on the slope the eye sees there, ink where the mask takes it and the white edge's paper, lit the same way, elsewhere within the edge (each no brighter than white); ridges finer than the pixels show each slope's average light (`means`, `ARC_RIDGE_FADE`) in the average of the lines it shows (`screenMean`: half of them, as many more or fewer as the design moves on across half a ridge), and bands finer than them fade as step 1's do. NoteView repaints it on either tilt, the turn and the rotation (`paintBands`' key holds the light; the white edge's map is kept by identity); the export lights it the same way (`drawArc`'s `lit`, its turn only in perspective, as the ink's). Without WebGL it shows the plain bands at rest (`bandsByHand` ignores the light). Left out: depth or light settings, the moiré, and Realistic for the rest of the banknote.

## Data

- Everything is stored in the browser's IndexedDB (`src/lib/db.ts`), images as blobs, and nothing goes to a server. Projects therefore live in the browser they were made in. Use the Sample project button on the project list to get sample content anywhere (the code still calls it the demo, at `#/demo`; Demo mode is another thing, see Demo under Product decisions). The demo is built in code (`src/lib/demo.ts`; its artwork, the printed faces, bird portrait, flapping bird, star and bird's head, is drawn on a canvas in `src/lib/demoArt.ts` and stored under fixed ids, once a session), so it changes only with the app; the shared template in Supabase (`supabase/demo/`) is no longer read. It opens playing its playlist (only a demo with one does), and leaving it stops playback and goes back to flat. Keep Mixed angles (several sections with their own angles) out of the demo until Keller knows it can be printed; its watermark sits in almost white paper with a slight green tint, and its playlist has no Hold to light (Keller, 3 November). Its second banknote shows Partial reveal as Keller set it out: five frames up/down, three side to side, the two outer ones (only up/down shows them) special enough to notice, a small star between the big ones. Both have backs, drawn too (`DEMO_ART.backs`), the first's plain oval on the right, where the bird watermark shows through turned over. Tests can't draw on a canvas, so they mock `createDemoProject` with a plain banknote. When a feature lands, consider showing it in the demo.
- When you change a saved shape, add a migration in `migrateProject` (`src/lib/notes.ts`) so existing projects keep working. An open tab can still hold the old shape in memory until it reloads.
- Image hooks that read a module-level cache (`useImageUrl`, `useRelief`, NoteView's `useImageAspect`) work out the value while rendering and, when it was missing, re-check in their effect: another view can fill the cache between this one's render and its effect, and the React Compiler won't recompute it without a state change.
- **Display copies** (`src/lib/images.ts`; 3 November, after large uploads made tilting stutter as the browser unpacked them whole again and again): never draw an uploaded original on screen. Every view passes `useImageUrl` (or `loadImageUrl`; the print preview through `loadArtwork` and `framePx`) the device pixels it draws the image across (`devicePx`, `designPx`, `THUMB_PX`) and gets the smallest display copy at least that big (256 to 4096 px on the long side, doubling), or the original past the largest; SVGs, which draw sharp at any size, and browsers that can't run the worker, get the original. Export is the exception: it draws the originals, at the full resolution they were uploaded at (Keller, 3 November), and reads the watermark and magnetic ink from the whole image too (`exportRelief`, `exportInkMask`: up to 8192 px, an SVG at least as big as the video draws it), afresh and not kept. Copies are made off the main thread (`src/lib/imageWorker.ts`, driven by `src/lib/imageWork.ts`), JPEG for opaque images and WebP for ones that show through, and kept only in this browser's own IndexedDB store (`of-thread-display-copies`, by image id and file size), never uploaded or saved in projects, so the original stays as uploaded. A new upload starts its copies at once, and `ThreadArt` gets every frame's ready ahead (`useWarmImages`), so a tilt never comes to one late. The watermark, magnetic ink and continuous check read their pixels from a bitmap the worker shrinks from the original (`pictureOf`), never from a compressed copy. Five 4000 px frames played at 44–55 fps with freezes up to 0.6 s before; with copies, a steady 60 fps.
- Every image a banknote uses must be listed by `projectImageIds` (`src/cloud/repository.ts`), or it isn't uploaded on save or copied from the demo, and by `noteImageIds` and `copyNote` (`src/lib/store.ts`), so Duplicate gives the copy its own. A new image field goes in all three.
